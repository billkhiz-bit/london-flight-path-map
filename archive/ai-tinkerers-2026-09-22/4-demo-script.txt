THE STORY (three sentences - if you say nothing else, say these)
=================================================================

  I built a postcode-scoring API with a small AI assistant on it, and
  the assistant is only allowed to explain numbers it was handed.

  Forty lines of ordinary code check that it did - and if a single
  number in its answer isn't in the data, the whole answer is thrown
  away.

  That check was wrong three times, and nothing noticed, because
  nobody had ever tried to make it fail.

The three lessons, in the order the organisers asked for:
  WHAT I BUILT      - a data-first scoring engine; the AI lives in two
                      narrow places (inside: the assistant; around: the
                      coding agent that helped build it). In May I cut
                      five AI features to get there.
  HOW I BUILT IT    - Nova Lite is the presenter, the scoring function
                      is the source, forty lines of Python are the
                      control; a handful of Amazon services that sleep
                      until called; Claude Code wrote most of it behind
                      57 checks that run before every commit.
  BUILDER TAKEAWAY  - an instruction is not a control; a check that has
                      never gone red hasn't been tested; if you build
                      with an agent, don't record a fact - record a check.

JARGON CARD (one line each, in the order they come up)
=================================================================

  API           A way for one program to ask another for data. Mine is:
                send a postcode, get back numbers.
  endpoint      One address on an API. /v1/chat is the assistant's.
  JSON          The text format the numbers come back in. Curly
                brackets, "name": value. You will see it on screen.
  Lambda        A small program that runs on Amazon's servers only when
                called. Each of my endpoints is one. No server to look after.
  API Gateway   Amazon's front desk for the API: checks the key, counts
                usage, rate-limits, passes the request to the right Lambda.
  S3 / CloudFront  S3 is the file cabinet holding the website's files;
                CloudFront is the worldwide network that serves them fast.
  DynamoDB      A very fast lookup table. Holds the 2.7M UK postcodes and
                the per-postcode noise readings.
  Bedrock       Amazon's service for calling AI models. I call one
                model through it: Nova 2 Lite.
  model         The AI. It reads text in, writes text out. It does not
                know anything about postcodes - it only knows what I
                hand it in the request.
  prompt        The written instructions I give the model. Mine says
                "only use the numbers in the data; never invent one".
  temperature   How adventurous the model is allowed to be. 0.2 is low:
                boring on purpose.
  grounded      My word for "every number in the answer can be pointed
                to in the data the model was given". True or false.
  pytest        Runs the automated tests and prints pass or fail.
  CloudWatch    Where Amazon keeps the logs - the lines my code prints
                while it runs in production.
  preflight     My name for the 57 checks that run before any code is
                saved to the project. 45 must pass ("blocking"); 12
                only warn ("advisory").
  gate / check  One of those 57. Same thing.
  red / green   A check failing / passing. "Prove it goes red" means:
                break the thing on purpose, watch the check fail, fix it,
                watch it pass. Only then trust it.
  Claude Code   The coding agent I build with. It writes and edits code
                in the project; I direct it and the checks police it.
  memory file   A note Claude Code keeps between sessions so it doesn't
                repeat a mistake. I keep about eighty for this project.
  credits       AWS credits - prepaid usage. The hackathon gave $200;
                the five AI features were burning $80-115 a month.

=================================================================
Q&A - likely questions, plain answers
=================================================================
Short sentences. Every technical word is explained where it is used.
Two of tonight's sponsors sell "guardrails" for AI, so expect the
first two questions.

ABOUT THE FORTY-LINE CHECK

Q  Why write your own check instead of using a ready-made guardrails
   tool?
A  Because the mistakes were about what the numbers MEAN. "12 of 33"
   is a rank, not a price. "50" is not the same as "5.0". A general
   tool can't know that; it doesn't know what's in my data. My check
   is forty lines because my data has one shape. A big tool would add
   a lot to do less.

Q  Why not get a second AI to check the first one?
A  A second AI is another set of instructions, and instructions are
   what failed. My check is plain code: it does the same thing every
   time, costs nothing, and takes no time. And if it's unsure, nothing
   goes out. A judging AI, when unsure, tends to let things through.

Q  What does the check miss?
A  A real number with the wrong label. If the model said "road noise
   is 6.4 decibels" when 6.4 is actually the quiet score, the check
   would pass it - the number is in the data. It catches the worst
   failure: a confident number that came from nowhere.

Q  Why throw the whole answer away? Why not add a warning?
A  A warning next to a made-up number still shows the number. People
   read the number and skip the warning. On a question about
   someone's home, no answer beats a wrong answer with a footnote.

Q  So it throws away correct answers too?
A  Yes - you saw it. "Fifty out of a hundred" was right, and it went
   in the bin. That's the price. For this product I pay it. For a
   different product I might not.

Q  How fast is the check?
A  Instant. It's comparing two lists of numbers. The slow part is the
   AI itself, about a second.

Q  Would it work with a different AI?
A  Yes. It never looks at which AI answered. It only looks at the
   words that came out and the data that went in. Swap the model and
   nothing in those forty lines changes.

Q  How did you find the third hole?
A  Rehearsing this demo. I asked a question expecting it to be
   refused, and it was accepted - for a reason that turned out to be
   wrong. I wrote a test that failed, then fixed the code.

Q  Does the AI still make things up?
A  Rarely now. I tried eight leading questions three times each; it
   got past the instructions once in twenty-four. The instructions
   hold most days. The check is there for the day they don't.

Q  Could someone type instructions into the question box to trick it?
A  They could make it SAY something odd, yes. But it has no tools, no
   memory, and no data except what I hand it, and a question can't be
   longer than 500 characters. The check limits the numbers it can
   say. The words it can say are not checked - I'd rather say that
   plainly than pretend otherwise.

ABOUT THE CHECKS AND THE CODING ASSISTANT

Q  What happens when one of the 57 checks fails?
A  The change can't be saved. There's no "save anyway". I fix the
   thing and run them again. It takes about a quarter of an hour, so
   I don't run them lightly - but I always run them.

Q  Isn't 57 checks slow?
A  Twenty-four minutes today, about fifteen normally. Yes, slow. But
   they've caught something in nearly every batch of changes since
   July. The fast version I had before was checking nothing.

Q  Give me a check that was "green while checking nothing".
A  The checklist itself, in July. Every result went through a command
   that always says "fine" at the end - like asking "any problems?"
   and only ever hearing the last person, who was the one holding the
   door. The whole list said PASS while running nothing. Nobody
   turned it off; it just decayed.

Q  How much of the code did the AI write?
A  Most of it. I decide what to build, read what it writes, and the
   57 checks police it. The decisions - what to score, what to throw
   away, what counts as "grounded" - are mine.

Q  When do you write code yourself and when does it?
A  I almost never type code now. I write the CHECK first - "when
   this is done, this must be true" - and the assistant makes it
   true. If we disagree about whether something works, the check
   decides, not either of us.

Q  How does the AI assistant get into your Amazon account?
A  It doesn't have an account. When it needs to touch the live system,
   it runs Amazon's normal command-line tools on my laptop with a
   pass that lives in a file outside the project. That pass belongs
   to one identity with a written list of what it may do, and
   everything on the list is limited to things named after this
   project. It can't see the bill, can't touch anything else, and
   can't change its own list - I do that, by hand, through the
   console with my phone.

Q  What stops it deleting everything?
A  Three things. A screening hook reads every command before it runs
   and blocks deletes outright. The assistant's own safety judgement
   refuses anything that looks like a production deploy and hands it
   to me. And Amazon's side only lets that pass touch this project's
   own things anyway. On the 16th of September its own safety check
   refused a deploy and I ran the one command myself. Today it
   refused to even fetch a file I'd just uploaded, so I checked it.
   That's the arrangement working.

Q  Does the AI deploy to production?
A  Not without my go-ahead, and not at all on its own initiative. The
   automated tests that run online have no Amazon pass at all - they
   can test, not deploy. Nothing reaches the live system except from
   my laptop, on my instruction.

Q  What does "record a check, not a fact" mean?
A  The assistant keeps notes between sessions. A note saying "the
   tests pass" is a fact - and it was false the day it was written.
   A note saying "before trusting a check, break the thing on purpose
   and watch the check fail" is a check. It's still true. The useful
   notes are all the second kind.

Q  What would you do differently?
A  Write the check before the instructions, not after the third real
   question. And prove every check can fail on the day it's written.
   The ones I did that for have held. The ones I didn't are the
   twelve.

ABOUT THE AMAZON SIDE AND THE FEATURES YOU CUT

Q  Why did you remove the AI features?
A  Two reasons, in this order. First, an AI summary on top of a
   carefully checked score adds an answer that varies and is
   sometimes wrong, and a business's auditors will challenge that
   first. Second, the five features were costing $80-115 a month in
   credits. The change is one commit from the 7th of May and says
   exactly that.

Q  What was the "multi-agent" part?
A  A sorting step in the chat: easy questions went to the small
   model, hard ones to the bigger, dearer model, and photos and
   documents to their own readers. Impressive in a demo, expensive
   per call, and the answers varied. It went with the rest.

Q  What does the assistant cost now?
A  About 25p per thousand questions. The check costs nothing.

Q  Why Amazon, and why nothing switched on all the time?
A  It started at Amazon's hackathon, so Amazon's tools were the
   starting point, and the AI model only lives there. And "nothing
   switched on" suits a service that's quiet most of the time: a
   normal server is like renting an office all night; my pieces wake
   up when asked and cost only when they work.

Q  Why is the AI in Virginia when everything else is in London?
A  Because that's where the model lives. It's the only piece outside
   the UK. Only the question and the score numbers travel there -
   nothing personal - and the privacy page says so.

Q  Couldn't you have just made the AI features cheaper?
A  Cheaper was the easy half. The problem was that they were
   sometimes wrong, and you can't budget your way out of that.
   Cutting to one narrow job - explain numbers you were handed -
   fixed both.

ABOUT THE MODEL AND THE STACK

Q  Why a small model and not a bigger one?
A  The job is reading numbers back in a sentence. A bigger model
   makes things up more fluently, not less.

Q  Why does the assistant ask the scoring program directly rather
   than over the web?
A  So the data it hands the AI is the exact same thing the API would
   return - no second copy to drift - and no web call to time out.

Q  Why three sentences and "boring" settings?
A  Three sentences is enough to explain a score and not enough to
   write an essay on a public service that someone else pays for.
   "Boring" (a low creativity setting) is the goal.

Q  Where does the data come from?
A  All from official bodies, all free to reuse with credit: the
   statistics office for postcodes and crime, the environment
   department for noise and air, the Environment Agency for flood,
   the Land Registry for prices, the education department for
   schools, the transport department for stations. Each is pulled by
   a script that can also re-check the published number against the
   source.

Q  Is it open source?
A  The code is public to read; the licence says all rights reserved,
   so it's "source-available" rather than open source. The check
   itself is forty lines - take the idea, you don't need my code.
